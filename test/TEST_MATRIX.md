# Матрица проверок Space Trace

Тесты разделены по границам отказа. `unit` проверяет разбор и конфигурацию, `integration` запускает реальный PyQGIS и пишет слои в системную временную папку, `ui` посылает реальные события мыши виджетам Qt, `e2e` загружает плагин в отдельный процесс QGIS и нажимает действие в его панели. Обычный прогон использует фиктивный клиент SpaceTrack. Режим `live` запускается только отдельной командой и читает учётные данные через Python `keyring` из хранилища текущей ОС.

## Состояние после реализации (27 октября 2026)

- `scripts/test-windows.ps1`: 294 unit, integration и Qt UI проверки прошли.
- `scripts/test-gui-e2e-windows.ps1 -Mode offline`: 7 сценариев прошли, включая сохранение проекта и открытие его в новом процессе QGIS.
- `scripts/test-gui-e2e-windows.ps1 -Mode mock-api`: 8 сценариев прошли, включая поиск, фильтры, мультивыбор, повтор после ошибки и частичный сбой пакета.
- `live`: 2 сценария прошли после обновления учётных данных. QGIS выполнил поиск NORAD 25544 через SpaceTrack, выбрал результат и создал слои по ответу API.

Аудит U/ST/F/GP ниже зафиксирован до реализации. Его слова «Пробел» и «Частично» отражают исходное состояние; актуальное покрытие проверяется тестами и сценариями выше. Нативный диалог выбора файла Windows и визуальная отрисовка карты в интерактивном сеансе остаются ручными проверками; QGIS E2E автоматизирует кнопки плагина и проверяет данные слоёв.

## Исходный аудит сценариев

Ниже — план новых тестов. Статус **частично** означает, что типовой успешный путь уже проверен, но указанный вариант отсутствует. **Пробел** означает, что автоматической проверки варианта нет. P0 — риск неверного результата, потери данных или слишком широкого запроса; P1 — важная пользовательская операция; P2 — редкий или косметический случай. Найденные по коду дефекты здесь обозначены как гипотезы до воспроизведения тестом.

### SpaceTrack: конструктор фильтров

Конструктор предлагает 24 поля. Проверяем каждый допустимый оператор хотя бы на одном представителе типа; остальные поля прогоняем параметризованным тестом отображения, преобразования имени в API и допустимых операторов. Для `LIKE`, дат и `NULL` отдельно проверяем фактический аргумент `satcat`, а не только текст в виджете.

| Тип | Поля | Операторы UI | Нужные значения и границы |
| --- | --- | --- | --- |
| Целое | NORAD_CAT_ID, APOGEE, PERIGEE, COMMENTCODE, RCSVALUE, FILE, LAUNCH_YEAR, LAUNCH_NUM, OBJECT_NUMBER | =, !=, <, > | 0, положительное, отрицательное, нечисловое, пустое |
| Дробное | PERIOD, INCLINATION | =, !=, <, > | 0, 90.5, отрицательное, `nan`/`inf`, неверная строка |
| Дата | LAUNCH, DECAY | =, !=, <, >, IS NULL, IS NOT NULL | YYYY-MM-DD, 29 февраля, невозможная дата, пустое, NULL |
| Строка | INTLDES, OBJECT_TYPE, SATNAME, COUNTRY, SITE, COMMENT, RCS_SIZE, LAUNCH_PIECE, OBJECT_NAME, OBJECT_ID | =, !=, LIKE | пустое, пробелы, `%`, спецсимволы и Unicode |
| Перечисление | CURRENT | =, != | Y, N, нижний регистр и неверное значение |

Реальный SpaceTrack оставляем отдельным узким smoke-прогоном: авторизация, точный поиск по одному NORAD ID и получение одного текущего GP. Широкие запросы Active, все лимиты и массовые фильтры проверяются фиктивным клиентом. Нестабильные ответы сервиса и сетевые ошибки воспроизводятся контролируемыми заглушками. Секреты читаются через `keyring` только в явно запущенном режиме `live`.

### Порядок реализации

1. **Сначала воспроизвести P0:** U01, U02, U05, U06, U08, U10, ST06, ST07, ST14, F01. Исправить подтверждённое поведение и закрепить тестами.
2. **Затем закрыть полную функциональность API:** ST01–ST05, ST08–ST13, F02–F07 и GP01–GP05. В основном использовать фальшивый клиент и реальные Qt-клики.
3. **Затем расширить вычисления и QGIS:** U03–U04, U07, U09, U11–U24 и GP06. Сквозные тесты оставить короткими, а комбинации форматов проверять параметризацией на уровне PyQGIS.

## Запуск на Windows

В PowerShell из корня репозитория:

```powershell
./scripts/test-windows.ps1 -QgisRoot 'F:\QGIS'
./scripts/test-gui-e2e-windows.ps1 -QgisRoot 'F:\QGIS'
./scripts/test-gui-e2e-windows.ps1 -Mode mock-api -QgisRoot 'F:\QGIS'
```

Первый скрипт выполняет unit, integration и Qt UI. Второй запускает полноценный QGIS с временным профилем и ссылкой на плагин; рабочий профиль `spacetrace` не трогается. Оба скрипта чистят созданные временные файлы. Необязательные бенчмарки: `F:\QGIS\bin\python-qgis-ltr.bat -m pytest test/benchmark` с `--benchmark-storage` в системной временной папке.

Для живого прогона один раз выполните `./scripts/spacetrack-credentials-windows.ps1 -Action set`, введите логин и пароль в локальном терминале, затем `./scripts/test-gui-e2e-windows.ps1 -Mode live`. Команда `-Action status` проверяет наличие записи, не показывая её содержимое; `-Action delete` удаляет её. Те же команды доступны как задачи VS Code. Пароль не передаётся аргументом командной строки и не записывается в репозиторий.
